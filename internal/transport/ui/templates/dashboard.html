Integrity Coverage

Metric Value Meaning
Oldest unverified {{if ne .Data.OldestUnverifiedAge 0}}{{formatDuration .Data.OldestUnverifiedAge}}{{else}}—{{end}} How long the most overdue reachable copy has gone unverified. A copy that has never been checked counts from when it was written, so this covers the whole reachable backlog rather than only what the sweep has already touched. Rises when the scrubber cannot keep pace, and falls once it verifies the copy at the head of the queue.
Never verified {{if ne .Data.NeverVerifiedCopies 0}}{{formatNumber .Data.NeverVerifiedCopies}}{{else}}—{{end}} Reachable copies that have a content hash but have never been checked against it. On a busy fleet this stays non-zero: newly written copies are unverified until the sweep reaches them, and they are deliberately queued behind older data. A steady value is healthy; a climbing one you did not cause is not.
Unreachable {{if ne .Data.DeferredCopies 0}}{{formatNumber .Data.DeferredCopies}}{{else}}—{{end}} Copies the sweep cannot read because their backend is over its usage limit. They are excluded from the two figures above, because a copy that can never be stamped would pin the age to the clock and no amount of scrubbing would lower it. The sweep will not clear this on its own: raise the backend's limit or wait for the period to roll over.
Checks run {{printf "%.0f" .Integrity.ChecksTotal}} Hash comparisons the scrubber has performed. Objects are sampled randomly with replacement on each run, so this counts operations, not distinct objects.
Mismatches {{if gt .Integrity.ErrorsTotal 0.0}}{{printf "%.0f" .Integrity.ErrorsTotal}}{{else}}0{{end}} Hash mismatches detected. Mismatches divided by checks run is a valid corruption rate, regardless of how often the same object was sampled.
